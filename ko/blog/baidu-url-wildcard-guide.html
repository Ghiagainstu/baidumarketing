모든 클릭 추적하기: 바이두 URL 와일드카드 완벽 가이드

2023년 5월 19일 약 7분 검색 광고 Baidu PPC Pro 팀

바이두 광고의 모든 클릭에는 정보가 담겨 있습니다. 어떤 키워드가 클릭을 유발했나요? 어떤 광고그룹인가요? 어떤 캠페인인가요? 이 질문에 대한 답은 바이두 플랫폼 안에 존재하지만, 이를 귀하의 애널리틱스 시스템으로 가져오려면 URL 와일드카드가 필요합니다.

Baidu는 키워드 랜딩페이지 URL, 소재 URL, 모바일 URL에 삽입할 수 있는 9개의 활성 와일드카드 파라미터를 지원합니다. 사용자가 광고를 클릭하면 각 와일드카드는 실시간으로 해당 값으로 치환되며, 애널리틱스 플랫폼이 전환을 올바른 키워드, 광고그룹, 캠페인으로 귀속시킬 수 있게 됩니다.

이제 모든 와일드카드 파라미터의 완전한 정리와 사용 방법, 그리고 수백만 달러의 Baidu 광고비를 운영하며 정립한 모범 사례를 소개합니다.

🔍 바이두 URL 와일드카드란?

URL 와일드카드는 광고가 클릭될 때 Baidu가 실제 값으로 자동 치환하는 플레이스홀더 파라미터입니다. 동적 변수라고 생각하시면 됩니다. 랜딩페이지 URL에 플레이스홀더를 넣어두면, Baidu가 클릭되는 순간 실제 값을 채워 넣습니다.

기본 개념은 Google Ads의 ValueTrack 파라미터와 비슷하지만, 구체적인 파라미터와 작동 방식은 상당히 다릅니다. Baidu 와일드카드는 계정 ID부터 개별 키워드 변형까지 계정 계층의 모든 단계에서 추적을 지원합니다.

💡
핵심 인사이트: URL 와일드카드는 키워드 랜딩페이지 URL, 소재(광고) 랜딩페이지 URL, 모바일 URL, 그리고 추가 소재의 경로 하위체인에서 작동합니다. 단, 디스플레이 URL에서는 작동하지 않습니다.

📋 전체 와일드카드 레퍼런스

다음은 Baidu 검색 광고에서 지원하는 모든 활성 와일드카드 파라미터와 그 치환 값, 일반적인 활용 사례입니다.

파라미터 치환되는 값 적합한 용도
{userid} 계정 ID(전역 고유) 다계정 추적
{planid} 캠페인 ID(전역 고유) 캠페인 단위 귀속 분석
{unitid} 광고그룹 ID(전역 고유) 광고그룹 성과
{keywordid} 키워드 ID(전역 고유) 키워드 단위 ROI 추적
{creative} 소재(광고) ID 광고 카피 테스트
{matchtype} 1 = 정확일치, 2 = 구문일치 매치타입 성과
{dongtai} 1 = 동적 광고, 0 = 일반 동적 광고 모니터링
{crowdid} 오디언스 패키지 ID(0 = 없음) 오디언스 타겟팅 검증
{trig_flag} at / zx / nm 트래픽 확장 추적

키워드 인코딩 파라미터

두 가지 추가 파라미터는 서로 다른 문자 인코딩을 사용하는 랜딩페이지의 키워드 인코딩을 처리합니다. 중국어 키워드에는 매우 중요합니다.

파라미터 인코딩 예시 출력 사용 시점
{kw_enc} GBK → URL 인코딩 %CF%CA%BB%A8 랜딩페이지가 GBK 인코딩 사용
{kw_enc_utf8} UTF-8 → URL 인코딩 %E9%B2%9C%E8%8A%B1 랜딩페이지가 UTF-8 인코딩 사용
⚠️
인코딩 주의: Baidu의 기본 중국어 문자 인코딩은 UTF-8이 아닌 GBK입니다. 랜딩페이지가 UTF-8을 사용한다면(대부분의 최신 웹사이트가 그렇듯) {kw_enc} 대신 {kw_enc_utf8}을 사용하세요. 잘못된 인코딩을 사용하면 깨진 문자가 발생해 애널리틱스 데이터가 손상됩니다.

⚙️ URL 와일드카드 작동 방식: 실전 예시

실제 시나리오를 단계별로 살펴보겠습니다. 원래의 키워드 랜딩페이지 URL은 다음과 같습니다.

http://www.yoursite.com

여러 와일드카드 파라미터를 추가하면 URL은 다음과 같이 바뀝니다.

http://www.yoursite.com/?a_keywordid={keywordid}&a_creative={creative}&a_matchtype={matchtype}&a_dongtai={dongtai}

사용자가 광고를 클릭하면 Baidu는 각 와일드카드를 실제 값으로 치환합니다. 서버로 전송되는 요청은 다음과 같습니다.

http://www.yoursite.com/?a_keywordid=123456789&a_creative=98765432&a_matchtype=1&a_dongtai=0

이제 애널리틱스 플랫폼은 어떤 키워드(ID 123456789)가 클릭을 유발했는지, 어떤 소재(98765432)가 노출되었는지, 정확일치(1)였는지, 동적 광고가 아닌(0) 것인지 정확히 알 수 있습니다.

🔗 바이두 와일드카드와 Google UTM 파라미터 결합

Google Analytics나 다른 UTM 기반 애널리틱스 플랫폼을 사용한다면, Baidu URL 와일드카드 시스템은 표준 UTM 파라미터와 완벽하게 함께 작동합니다. 같은 URL에 섞어 쓸 수 있습니다.

https://www.yoursite.com/?utm_source=baidu&utm_medium=cpc&utm_campaign={planid}&utm_term={kw_enc_utf8}&utm_content={creative}

이 방식은 두 가지 이점을 모두 제공합니다. 애널리틱스 대시보드의 표준화된 UTM 리포팅과, 귀하의 서버 측 로직이나 서드파티 어트리뷰션 도구에서 처리할 수 있는 Baidu 고유 추적 파라미터를 결합합니다.

✅
전문가 팁: 최소한의 기준으로 {keywordid}와 {planid}를 항상 포함하세요. 이 두 파라미터만으로도 전환을 키워드와 캠페인 단위로 귀속시킬 수 있으며, 사용 사례의 90%를 커버합니다.

🚫 폐기된 와일드카드(더 이상 지원 안 함)

Baidu는 플랫폼이 발전하면서 여러 와일드카드를 폐기했습니다. 이전 계정 설정에서 이러한 항목을 발견한다면 제거하세요. 더 이상 어떤 값도 전달하지 않습니다.

{pagenum} {adposition} {mediatype} {placement} {bidurl} {haoci} {abtest}
⚠️
경고: 폐기된 와일드카드를 사용한다고 오류가 발생하지는 않지만, 값도 채워지지 않습니다. 이는 추적 범위가 제대로 잡혔다는 잘못된 확신을 줍니다. 애널리틱스 리포트에 캠페인 데이터가 누락된 클릭만 표시되어, 차라리 추적을 하지 않는 것보다 더 나쁩니다.

📏 URL 와일드카드 올바르게 사용하는 7가지 규칙

  1. 와일드카드는 대소문자를 구분합니다. {Creative}는 작동하지 않으며 {creative}(모두 소문자)를 사용하세요. Baidu는 파라미터 이름에 대한 대소문자 정규화를 수행하지 않습니다.
  2. 동일한 와일드카드를 여러 번 쓰면 같은 값이 반복됩니다. 같은 URL에 {keywordid}를 두 번 넣으면 두 곳 모두 같은 키워드 ID로 치환됩니다.
  3. 잘못된 와일드카드는 조용히 무시됩니다. 오타 난 파라미터를 제출하면 Baidu는 이를 URL에 그대로 일반 텍스트로 남겨둡니다. 오류 메시지도 경고도 없습니다.
  4. 와일드카드는 URL 연결 상태에 영향하지 않습니다. Baidu는 최종 URL에 접근 가능한지 검증하지 않습니다. 랜딩페이지가 가능한 모든 파라미터 조합을 처리하는지 확인하세요.
  5. 디스플레이 URL은 와일드카드를 지원하지 않습니다. 랜딩페이지 URL, 모바일 URL, 경로 하위체인에서만 작동합니다.
  6. 먼저 단일 파라미터로 테스트하세요. 와일드카드 하나를 적용한 뒤 애널리틱스에서 작동하는지 확인한 다음 추가하세요. 9개 파라미터를 한꺼번에 디버깅하는 것은 고통스럽습니다.
  7. 쿼리 파라미터 접두사를 사용하세요. 그대로 된 ID(?123) 대신 명명된 파라미터(?kw_id=123)를 사용하세요. 다른 URL 파라미터와 충돌하는 것을 방지합니다.

🌏 중국어 키워드 인코딩 고려사항

우리가 가장 흔히 보는 실수는 중국어 키워드에 잘못된 인코딩 파라미터를 선택하는 것입니다. Baidu 기본 인코딩은 GBK이지만, 대부분의 최신 랜딩페이지는 UTF-8을 사용합니다. UTF-8 랜딩페이지에 {kw_enc}을 사용하면 애널리틱스에 쓸 수 없는 깨지고 이중 인코딩된 문자가 생성됩니다.

선택 방법은 다음과 같습니다.

  • 랜딩페이지가 GBK를 사용하는 경우: {kw_enc}을 사용하세요. URL 디코딩 후 키워드는 GBK 형식이 됩니다.
  • 랜딩페이지가 UTF-8을 사용하는 경우(가장 흔함): {kw_enc_utf8}을 사용하세요. URL 디코딩 후 키워드는 UTF-8 형식이 됩니다.
  • 랜딩페이지의 인코딩을 확실히 모르는 경우: 페이지 HTML의 <meta charset> 태그를 확인하세요. utf-8(또는 UTF-8)이라고 되어 있다면 {kw_enc_utf8}을 사용하세요.

"URL 와일드카드를 제대로 설정하는 것은 Baidu PPC 계정에 적용할 수 있는 ROI가 가장 높은 기술적 변경 중 하나입니다. 적절한 추적 파라미터가 없으면 모든 최적화 결정이 추측에 기반하게 됩니다."

— Baidu PPC Pro 팀

🎯 오디언스 및 트래픽 확장 추적

두 가지 고급 파라미터는 대부분의 광고주가 놓치는 인사이트를 제공하므로 특별히 주목할 필요가 있습니다.

{crowdid} — 오디언스 타겟팅 검증

특정 오디언스 패키지를 타겟팅할 때 {crowdid}는 클릭한 사용자가 일치한 오디언스 패키지 ID를 반환하며, 일치한 오디언스가 없으면 0을 반환합니다. 오디언스 타겟팅이 실제로 작동하는지 검증하는 데 매우 유용합니다. crowdid가 0보다 큰 클릭의 비율을 의도한 타겟팅 범위와 비교할 수 있습니다.

{trig_flag} — 트래픽 확장 모니터링

이 파라미터는 클릭이 자동 트래픽 확장에서 왔는지 알려줍니다. 세 가지 가능한 값을 반환합니다. at(자동 트래픽 확장), zx(스마트 매칭), nm(일반 트래픽). 트래픽 확장 기능을 테스트 중이라면, 비용 대비 증분 가치를 측정하는 데 이 파라미터가 필수적입니다.

📋 핵심 요약

  • Baidu는 계정 계층 전반에 걸쳐 9개의 활성 URL 와일드카드 파라미터를 지원합니다
  • 최소 권장 설정: 키워드 귀속용 {keywordid} + 캠페인 귀속용 {planid}
  • Baidu 와일드카드와 Google UTM 파라미터를 결합해 듀얼 플랫폼 추적을 수행하세요
  • 파라미터는 대소문자를 구분하므로 항상 소문자를 사용하세요
  • UTF-8 랜딩페이지는 {kw_enc_utf8}, GBK는 {kw_enc}을 사용하세요
  • 폐기된 와일드카드 7개를 모두 활성 대안으로 교체하세요
  • 설정 문제를 격리하려면 파라미터를 하나씩 테스트하세요
